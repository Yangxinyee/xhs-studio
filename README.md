# xhs-studio

**English** | [中文](README.zh-CN.md)

A local workbench for **backing up** and **publishing** Xiaohongshu (RedNote) notes. Download every note under your own account (images / video plus title, body, topics and engagement counts), search them by title, and publish image or video notes from local files. Comes with a Streamlit GUI and a CLI.

Built on top of [ReaJason/xhs](https://github.com/ReaJason/xhs) — thanks to the original author.

> For backing up and managing **your own** content only. Respect Xiaohongshu's terms of service, keep request rates low, and do not use this to scrape other people's data.

## Why this exists

The main-site endpoints of the `xhs` library require an `x-s` signature generated by browser-side JavaScript. The library's built-in pure-Python signer no longer works for them (the API answers `{'code': -1}`), and the upstream examples rely on Playwright injecting `stealth.min.js` and calling the page's signing function, which is fragile. This project takes a steadier route:

| Feature | Approach | Signature needed? |
|---|---|---|
| Note list (first page) | Parse `__INITIAL_STATE__` from your profile page HTML | No |
| Note list (all) | Playwright opens your profile, auto-scrolls, and captures the `/user_posted` responses the page itself makes | No (the browser signs) |
| Note detail / download | `get_note_by_id_from_html` — parse the note page HTML | No |
| Publish image / video | Creator-platform endpoints + the library's built-in signer | Built-in signer works (tested) |

Two practical fixes on top: topics only render as tags when the body contains `#topic[话题]#` markers, and downloads save the text content alongside the media.

## Install

```bash
git clone https://github.com/Yangxinyee/xhs-studio.git
cd xhs-studio
pip install -r requirements.txt
playwright install chromium        # only needed for "Full refresh" (fetch all notes)
```

## Usage

### 1. Get your cookie

Log in to `xiaohongshu.com` **and** `creator.xiaohongshu.com` (the creator platform — publishing and auto-detecting your user id depend on its cookies), then DevTools → Network → any request → Request Headers → copy the whole `Cookie` value.

The cookie is stored only on your machine at `~/.xhs-studio/config.json`, which is git-ignored.

### 2. GUI

```bash
streamlit run app.py
```

- **Settings** — paste the cookie → Save (user id is detected automatically) → Test connection
- **Notes** — Quick refresh (first page) / Full refresh (scroll for everything) → search → select → download
- **Publish** — image or video notes with topics, scheduled posting and private mode (private by default; switch to public once you have checked the result)

Download layout:

```
~/xhs-notes/
└── <note title>/
    ├── <note title>.txt      # title, body, topics, likes/collects/comments, note_id
    ├── <note title>_0.png
    └── ...                   # video notes: <note title>.mp4
```

### 3. CLI

```bash
python -m xhs_studio.cli config --cookie "a1=...; web_session=...; ..."
python -m xhs_studio.cli list --all              # scroll for all notes and cache them
python -m xhs_studio.cli search "binary search"
python -m xhs_studio.cli download --title "binary search"
python -m xhs_studio.cli download --all

python -m xhs_studio.cli publish-image --title "Rule of 72" --desc "..." \
    --image rule72.jpg --topic investing --topic compounding    # private by default; add --public
python -m xhs_studio.cli publish-video --title "..." --desc "..." \
    --video a.mp4 --cover c.jpg --at "2026-09-12 10:00:00"
```

### 4. As a library

```python
from xhs_studio.client import make_client
from xhs_studio.notes import fetch_notes_quick, download_note
from xhs_studio.publish import publish_image_note, resolve_topics

client = make_client(cookie)
notes = fetch_notes_quick(client, user_id)
download_note(client, notes[0], "~/xhs-notes")

topics = resolve_topics(client, ["investing"])
publish_image_note(client, "Title", "Body", ["a.jpg"], topics, is_private=True)
```

## Known limitations

- Main-site endpoints that need a signature (site-wide search, comments, likes, …) are not provided.
- "Full refresh" needs Playwright. If you hit a captcha, turn off headless mode in Settings and solve it once in the browser window that opens.
- Xiaohongshu's endpoints change without notice; everything here was verified working in September 2026.
